# 实现说明（M0-M4 骨架已落地）

> 2026-09-21 ｜ 对应代码提交范围：`apps/server` `apps/web` `packages/shared` `deploy`

## 1. 已实现

**服务端（Fastify + TypeScript，零原生依赖）**

- 邀请码注册、scrypt 口令、JWT httpOnly Cookie、同源写操作校验、分接口限流
- 每日个人配额 + 全局日成本熔断；`usage_daily` 记账（提交预扣、成功落成本、失败退还）
- 上传链路：multipart → 类型/尺寸/像素总量校验 → 落盘 → 建 images 记录
- 持久化任务队列：任务表本身当队列，worker 并发上限、超时、可重试错误自动重排、进程重启回收中断任务
- SSE：按用户隔离、环形缓冲 200 条、`Last-Event-ID` 重放、15s 心跳、断线自动重连
- Provider 抽象层：统一 `ProviderRequest/ProviderResult`，按能力路由 + 失败降级；mock / Seedream / 万相三个适配器
- Agent：规划（规则式 mock 或任意 OpenAI 兼容端点）→ 校验器（白名单、参数 schema、事实补全、依赖清洗、环检测、拓扑排序）→ 执行器（服务端步骤入队、前端步骤下发指令等回执）
- 计划接口：确认执行、取消、单步重试、跳过并继续；错误码稳定
- 管理端：概览（今日成本/队列水位/上游可用状态）、用户配额调整、邀请码批量生成
- 生产模式下同一进程托管前端构建产物（同源，免 CORS）

**前端（React 19 + Vite + react-konva + zustand）**

- 设计 tokens 直接来自设计稿 §06（银盐五级灰阶 + 状态三色 + 等宽数字 + 显影缓动）
- 工具箱：工具列表（注册表驱动）、表单（注册表 `fields` 驱动）、上传（浏览器内 canvas 压缩出编辑副本与缩略图）、显影进度、前后对比滑杆、四宫格候选
- 编辑台：Konva 画布（光标锚点缩放、拖拽平移、适配、`⌘0/⌘1`）、图层面板（选中/显隐/删除/上下移/不透明度滑块）、拖拽变换手柄（Konva Transformer + `lib/artboard.ts` 的矩阵换算）、撤销重做（快照栈 50）、前后对比、笔刷遮罩与矩形框选（像素空间绘制，09-24 起上传链路已通）、接触印样胶片条、自动保存（防抖 + 按版本记账）+ `⌘Z / ⇧⌘Z / ⌘S / [ ] / \` 快捷键
- Agent 面板：对话、计划卡片（步骤状态、成本、耗时、失败重试/跳过）、客户端步骤自动执行并回执
- 管理页：概览、邀请码、配额

**验证**

- `pnpm test`：97 例（75 服务端 + 22 前端）——计划校验器、规则式规划器、PNG 编解码、迁移与版本表、配额账本与退款幂等、任务超时取消、计划抢占锁、会话吊销、计划用例集，加上前端的画布矩阵与编辑器 store（纯逻辑，不需要浏览器）
- `pnpm --filter @retouch/server smoke`：30 项端到端断言，含"SSE 真的推到了事件""邀请码一次性""遮罩单独上传""隐私告知先 null 后落库""Agent 多步计划跑完"。越权用例现在**真的带第二个账号的 cookie**（403）并另测未登录（401），跨用户隔离有自动化覆盖了（原 §6 D-11 已销）
- 真机 UI 走查：登录 → 上传 → 抠图出结果 → 进编辑台 → Agent 三步计划（含浏览器端步骤）→ 撤销/重做

## 2. 与原设计的四处偏差

| #   | 原设计                                  | 现在                                                                 | 为什么                                                                                                 | 怎么回到原设计                                                                                                                                                      |
| --- | --------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | PostgreSQL + pg-boss                    | **node:sqlite**（Node 22 内置）+ 任务表当队列                        | 开发机没有 Docker、没有 VS 编译链，`better-sqlite3` 预编译包也拉不下来；不解决这个就一行代码都验证不了 | 数据库读写全部收口在 `apps/server/src/db/index.ts` 的 `run/get/all/tx` 四个出口 + `src/queue/`；换 Postgres 时改这两处与 SQL 方言（TEXT→JSONB），上层仓储与业务不动 |
| 2   | 服务端 sharp 做缩略图/编辑副本/导出合成 | **浏览器 canvas 生成** original/edit/thumb；导出走 Konva `toDataURL` | sharp 同样是原生依赖；而且编辑本来就在浏览器画布上，副本在本地生成反而少一次往返                       | 需要服务端合成时（如批量导出、无头生成）再引入 sharp，接口已按"服务端只存字节"设计，不冲突                                                                          |
| 3   | 换背景 = 抠图 + 背景生成两步            | 单次图像编辑调用（`replace_background` 内部拼提示词）                | 服务端没有像素合成能力；Seedream/万相这类模型本身能一步做背景替换                                      | 若实测边缘质量不够，改回 `split_layers`（已有，产出主体层+背景层两张图）+ 前端合成图层                                                                              |
| 4   | 内容审核用阿里云内容安全                | 默认 `none`；提供 `qwen-vl` 粗筛实现                                 | 少一个账号与 key，先把主链路跑通                                                                       | `apps/server/src/services/moderation.ts` 的 `checkImage` 里加一个分支即可，调用点（上传、生成结果）已经埋好                                                         |

另外两点小差异：Agent 编排没引入 LangGraph（按设计就是自研三段式，约 400 行，可单测）；Mock Provider 用手写的 `lib/png.ts` 产出**真实 PNG 字节**而不是占位字符串，这样断链时整条链路（含图片下载、画布渲染）都是真的。

## 3. 已知限制（诚实清单）

1. **两个真实上游适配器没跑过真 key**：Seedream 的 `image/mask_image/max_images` 字段、万相的编辑端点与是否接受 dataURL，都要按各家当前文档核对。改的时候只碰 `providers/*.ts`。
2. **需要公网图片 URL 的能力没有实现**：不少上游只收可访问的图片地址，而我们的 `/api/images/:id` 要登录 Cookie。原来 `lib/signurl.ts` 写好了 HMAC 签名外链，但**签发侧零调用**（所有适配器都走 dataURL），只剩校验侧挂在读图路由上 —— 那是纯粹的攻击面而没有收益。**09-24 已整块删掉**（连同"带 sig 就能免 Cookie 读图"那条旁路）。真要接只收 URL 的上游：在 `lib/` 里把签发与校验一起做回来，并让 `providers/*.ts` 真正去用 `ImageRef.url`，同时 `PUBLIC_BASE_URL` 得是真实域名（该变量目前无代码读取，已在 config 注释里标明）。
3. **调色是 Konva 核心滤镜的子集**：亮度/曝光/对比/饱和/黑白/色温（用 HSV 的 hue 近似）有效；**真锐化、高光阴影分离没有**，暗角与褪色用叠加矩形近似。要还原 Photoshop 级别，得换 WebGL 滤镜管线（推荐 `konva-filters` 或自写 shader）。
4. **多图融合的 UI 入口不完整**：后端与注册表都有 `merge_images`，但工具箱目前只能选一张当前图，选多张的交互还没做。
5. **前端产物已按路由拆分**（09-24）：编辑台懒加载，入口 `index` 399KB（gzip 126KB）+ `Editor` 372KB（gzip 116KB）+ `Admin` 3.3KB；未进编辑台时不下发 Konva。此前是 760KB（gzip 237KB）单 chunk。首屏 <2.5s（01 §7.2）目前只有体积证据，没有真实网络下的计时。
6. **移动端有三档但只量过数字**：≤1023 / ≤860 / ≤639 与横屏档都在，360/390/430/320 逐元素扫过右边缘、无横向溢出，编辑台抽屉在 360 铺满；但**遮罩笔刷与图层面板在小屏的手感没在真机上摸过**，`env(safe-area-inset-*)` 的表現也只能真机验（桌面恒为 0），`02 §6` 要的截图归档还欠着。
7. **SSE 单进程**：多实例部署时事件只在一个进程内广播，需要换 Postgres LISTEN/NOTIFY 或 Redis Pub/Sub（`lib/sse.ts` 已按可替换的 hub 写）。
8. **删除是彻底的，备份不是**：删图会连文件、行与三处引用一起清掉，但已写进 `VACUUM INTO` 快照与图片打包的那份要等 14 天滚动清掉。急删要么改 `BACKUP_DIR` 里的文件，要么调整保留期。账号注销（含整棵图片目录与配额记录）也已经能自助做，同样只留下备份里的副本。

## 4. 安全现状与已知边界

> 2026-09-24 从"我们做了哪些防护措施"扩成**威胁模型**：防护措施只是故事的一半，
> 一个自部署工具真正需要告诉运维的是"哪些攻击我们挡住了、哪些没挡、代价是什么"。

### 4.1 已经挡住的

| 面向                | 措施                                                                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话被盗用          | JWT httpOnly + SameSite=Lax（JS 读不到 cookie，跨站请求不带）；`users.token_version` 让注销/改密能**立刻**吊销已签发的 token（以前只能等 30 天自然过期）      |
| CSRF                | 所有非 GET 过同源校验（`app.ts:originGuard`）；生产再叠 `COOKIE_SECURE` + HTTPS                                                                               |
| 越权取图            | 每张图归属校验，跨用户 403、未登录 401；**冒烟里带第二个账号真实测过**（以前那条用例不带 cookie，只证明了未登录被拒）                                         |
| 口令库被拖          | scrypt（N=16384）而不是裸 bcrypt/md5；用户名枚举靠"查不到也跑一次 verify"拉平时间                                                                             |
| 上传炸内存 / 炸磁盘 | 单张 20MB + 单次请求总量 60MB + 4000 万像素上限（先嗅探再落盘）；上游返回的结果也有 48MB 硬顶                                                                 |
| 被刷爆账单          | 三类限流（登录/上传/任务）+ 个人日配额 + 全局日成本熔断；`TRUST_PROXY` 默认放行回环与内网段，否则反代后所有人共用一个限流桶                                   |
| 恶意内容扩散        | 审核服务故障时**成品图不放行**（fail-closed）而上传放行 —— 要发给别人看的那张宁停不错发；缺 key 直接拒绝启动而不是静默不审                                    |
| 源码泄露            | `sourcemap:false`（曾有 3.7MB TS 源码挂在 `/assets/*.map` 上，且被 `immutable` 缓存到撤不回来）；只有带内容哈希的 assets 才 `immutable`，html 一律 `no-cache` |
| 提权残留            | 角色一律读库不读 token，管理员降级即刻生效                                                                                                                    |

### 4.2 明确的边界（没挡的，以及为什么）

1. **信任每一个拿到邀请码的人**。这是邀请制小范围工具的立身前提，也是不做端到端加密、
   图片明文躺在 `$DATA_DIR/images/` 的理由。一旦要对外开放注册，§4.3 里几条要重估。
2. **没有审计日志**。谁在什么时候删了谁的什么，事后只能从 `x-request-id` 反查 pino 日志，
   而日志默认不落盘多久由容器驱动决定。**要合规审计就得自己接日志收集**。
3. **`/api/health` 与 `/api/config` 免鉴权**。探针要打得到，代价是上游可用性、planner 与
   moderation 配置对外可见。别在这台机器上放不能公开的东西。
4. **备份是明文副本**，且保留 14 天。用户删图/注销后，备份里那份还要活最多 14 天；
   `BACKUP_DIR` 的磁盘权限与异地同步（`RCLONE_REMOTE`）由部署者负责，代码管不到。
5. **SQLite 单写**。`busy_timeout=5000` 挡得住短暂争用，挡不住有人拿外部脚本长时间
   读写同一个库 —— 那会直接 `database is locked`（测试现在因为踩过这个而在
   `NODE_ENV=test` 缺显式路径时拒绝启动）。
6. **SSE 单进程广播**：多实例部署时事件只在一个进程内发，进度会看起来"丢"。
   真要横向扩展得换 Postgres LISTEN/NOTIFY 或 Redis Pub/Sub。
7. **没有漏洞披露渠道与 LICENSE**（LICENSE 待补，见 [05](./05-修复与收尾计划.md) 的 6.7）。

### 4.3 分享前必做（顺序即优先级）

1. `JWT_SECRET` 换随机值（`openssl rand -hex 32`）—— 不换的话**生产启动现在会直接拒绝**，
   不再只是文档里的一句提醒。
2. `SITE_ADDRESS` + HTTPS（compose 缺 `SITE_ADDRESS` 会报错退出，不会静默签 localhost 证书）。
3. `COOKIE_SECURE=true`。
4. `MODERATION=qwen-vl`（并确认 `LLM_API_KEY` 有效）。
5. 跑一次 `./deploy/backup.sh` **和一次真实恢复演练**（`deploy/restore.sh`），
   没演练过的备份不算备份。
6. 给每人设合理 `PER_USER_DAILY_CALLS`，确认 `DAILY_BUDGET_YUAN` 是你能接受的损失上限。
7. 配 cron 跑 `cost-report`，让成本与失败率异常会主动找人（退出码 0/2/3）。
