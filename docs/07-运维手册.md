# 07 · 运维手册

自部署这套东西要长期跑，靠的不是"记得住"，是这几段能照着敲的命令。
使用向的说明在 [04-使用文档.md](./04-使用文档.md)，缺陷与欠账在 [05-修复与收尾计划.md](./05-修复与收尾计划.md)。

---

## 1. 部署

```bash
cp .env.example .env      # 必填：JWT_SECRET、PUBLIC_BASE_URL、SITE_ADDRESS
docker compose up -d --build
```

三个必填项各自的后果，写清楚免得踩：

| 变量              | 不填会怎样                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `JWT_SECRET`      | compose 直接拒绝启动（`:?` 守卫）。改了它 = 所有登录会话立刻失效，没人被锁死但要重新登录 |
| `PUBLIC_BASE_URL` | 上游模型回拉图片时会拿到错误地址；本地 Mock 不受影响，接真 key 必炸                      |
| `SITE_ADDRESS`    | 同样被 `:?` 拦住。以前不拦，会静默签一个 `localhost` 证书，站点等于没上线                |

Caddy 负责 HTTPS 与 **SSE 不缓冲**（`deploy/Caddyfile` 里的 `flush_interval -1`）。
这一条丢了的话前端进度条会"卡住不动直到完成"，看起来像后端坏了 —— 排查顺序先看这里。

## 2. 数据在哪

| 东西   | 位置                                                                                |
| ------ | ----------------------------------------------------------------------------------- |
| 数据库 | `$SQLITE_PATH`（compose 里 `/data/retouch.db`），WAL 模式，旁边会有 `-wal` / `-shm` |
| 图片   | `$DATA_DIR/images/<userId>/<imageId>.<ext>`，一个用户一个目录                       |
| 备份   | `$BACKUP_DIR`（compose 里 `/data/backups`，在卷里面）                               |

库的 schema 版本记在 `PRAGMA user_version` 里，不是某张表 —— 用 `sqlite3 retouch.db 'PRAGMA user_version'` 能直接看到当前是几。

## 3. 备份与恢复

```bash
docker compose exec app /app/deploy/backup.sh     # 每天该跑一次（配 cron）
```

产出两样：`retouch-<时间戳>.db`（`VACUUM INTO` 的一致性快照，不是文件拷贝）与
`images-<时间戳>.tgz`，并更新软链 `latest.db`。保留 14 天。
设了 `RCLONE_REMOTE` 会尝试同步到对象存储，但**镜像里没有 rclone**，会打一行告警跳过
（要异地备份就在宿主机上挂个 cron 跑 rclone，别指望容器里那个）。

恢复：

```bash
docker compose stop app
docker compose exec app /app/deploy/restore.sh /data/backups/latest.db --force
docker compose up -d app
```

`restore.sh` 会先把快照的**行数与 user_version 打出来**再动手，目标库已存在时必须 `--force`。
加 `--images images-<时间戳>.tgz` 连图片目录一起还原。

**恢复前必须停服**：跑着的进程会把旧的 WAL 写回来，你会得到一个混着两个时间的库。

演练过的标准是：恢复后能登录、能看到旧图、`/api/health` 正常。**没演练过的备份不算备份**。

## 4. 每日巡检（两分钟）

```bash
pnpm --filter @retouch/server cost-report            # 今天
pnpm --filter @retouch/server cost-report --date=2026-09-21
```

输出：任务数（成功/失败）、计费次数、成本对预算的百分比、每人花费前列、按工具的成本、
失败原因按错误码归类，以及 `charged=0` 的**未结算账**（那是漏退的征兆）。

退出码是给 cron 用的：`0` 正常 · `2` 成本达预算 80% · `3` 当天失败率过半。

```cron
0 8 * * * cd /srv/retouch && pnpm --filter @retouch/server cost-report >> /var/log/retouch-cost.log 2>&1 || 你的通知命令
```

日期口径：报表跟着**服务器本地日**切（容器默认 UTC → 国内是早上 8 点换一天）。

## 5. 出事了怎么查

### 5.1 先要一个请求编号

每个请求都有短编号：响应头 `x-request-id`，日志里 `reqId` 字段。
**500 的提示文案里直接带编号**（`服务内部错误（编号 4f2a1c9b）`），用户截图就能对上日志行。
4xx 不带 —— 那些提示本来就是给人看的。

```bash
docker compose logs --since 30m app | grep 4f2a1c9b
```

日志是 pino 的结构化 JSON，`level` 50=error / 40=warn。级别由 `LOG_LEVEL` 控制
（注意它直接读 `process.env`，不在 config 的校验表里）。

### 5.2 看整体状态

```bash
curl -s $BASE/api/health
```

```json
{
  "status": "up",
  "worker": { "running": 2, "concurrency": 3 },
  "sseClients": 4,
  "providers": [{ "id": "seedream", "available": false }],
  "planner": "mock",
  "moderation": "qwen-vl"
}
```

- `worker.running` 长期贴着 `concurrency` → 队列在堵，看上游是不是慢。
- `providers[].available=false` → 没配 key（不是坏了）。
- `sseClients=0` 而用户在页面上等进度 → 中间代理把 SSE 缓冲了，回 §1。
- `/api/health` 与 `/api/config` **免鉴权**（要探针能打到），所以别在这台机器上放敏感信息。

### 5.3 常见故障与真因

| 现象                                                     | 先看哪里                                                                                                                                       |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 所有人都出不了图，报 `MODERATION_UNAVAILABLE`            | 审核服务挂了。**成品图按不放行处理是刻意的**（宁停不错发给别人的图），查 `LLM_API_KEY` 与到 `LLM_BASE_URL` 的网络                              |
| 起不来，日志说 `MODERATION=qwen-vl 但 LLM_API_KEY 为空`  | 配置自相矛盾，要么补 key 要么显式 `MODERATION=none`                                                                                            |
| 起不来，日志说"数据库版本比代码更新"                     | 有人回滚了代码或拿新库配老代码。恢复代码或补迁移，**别手改 `user_version`**                                                                    |
| 上传大图报 413                                           | 单张看 `MAX_UPLOAD_MB`，一次请求总量看 `MAX_UPLOAD_TOTAL_MB`（原图+编辑副本+缩略+遮罩是一起发的）                                              |
| 登录/上传莫名被限流                                      | 前面有反代却没设 `TRUST_PROXY` → 所有人共用一个桶；或 `TRUST_PROXY` 写了 `private` 这种关键字（Fastify 只认 IP/CIDR 列表，写错会**启动即崩**） |
| 任务卡在 running，重启后报"服务重启导致中断，配额已退回" | 正常回收路径：`reapStaleRunning()` 会把 running 判失败并退还预扣                                                                               |
| `database is locked`                                     | 有第二个进程占着同一个库（最常见：忘了改 `SQLITE_PATH` 就跑脚本/测试）。测试现在会在 `NODE_ENV=test` 且没显式给路径时直接拒绝启动              |
| 改了代码但前端没变                                       | 静态产物是构建期烘进镜像的，要 `--build` 重打；开发期用 `pnpm dev` 才有热更                                                                    |
| 用户说"图删了还在"                                       | 备份里的副本要等 14 天滚动清（`§3`），或他删的是项目而不是原图（删项目刻意不带走可能被共用的原图）                                             |

## 6. 升级与迁移

发新版前：

```bash
./deploy/backup.sh          # 先有一个能恢复的点
```

启动时 `PRAGMA user_version` 低于代码里的迁移表就按顺序补，每条迁移和它的版本号写在
**同一个事务**里，失败会回滚并点名是哪条 —— 所以升级失败通常库还停在旧版本，
不需要手工修。新增字段一律走 `MIGRATIONS` 数组尾部追加，不要改基线 `schema.sql`
（基线只在 v0 新库跑一次，改了老库不会生效）。

## 7. 环境变量全表

`config.ts` 会校验类型并给默认值；校验失败会打印每个字段的问题再退出。

### 运行

| 变量              | 默认                                          | 说明                                           |
| ----------------- | --------------------------------------------- | ---------------------------------------------- |
| `NODE_ENV`        | `development`                                 | `production` 时才会因 `MODERATION=none` 打告警 |
| `HOST` / `PORT`   | `127.0.0.1` / `8787`                          | 容器里是 `0.0.0.0`                             |
| `LOG_LEVEL`       | 生产 `warn`，其它 `info`                      | **直接读 `process.env`，不在 config 校验表里** |
| `JWT_SECRET`      | 一个显式不安全的默认值                        | 生产必须换；改了=全体重新登录                  |
| `COOKIE_SECURE`   | `false`                                       | 上 HTTPS 后设 `true`                           |
| `TRUST_PROXY`     | `127.0.0.1, ::1, 10/8, 172.16/12, 192.168/16` | **只接受 IP/CIDR 列表**；裸跑设 `false`        |
| `PUBLIC_BASE_URL` | `http://127.0.0.1:8787`                       | 上游回拉图片用，必须公网可达                   |
| `SITE_ADDRESS`    | —（compose 用）                               | Caddy 的站点地址，不进 config                  |

### 存储

| 变量            | 默认                | 说明                                    |
| --------------- | ------------------- | --------------------------------------- |
| `DATA_DIR`      | `data`              | 图片目录的根                            |
| `SQLITE_PATH`   | `data/retouch.db`   | 相对路径按仓库根解析；容器里必须指到卷  |
| `DATABASE_URL`  | —                   | **预留**，当前实现走 SQLite，设了也不读 |
| `BACKUP_DIR`    | —（`backup.sh` 读） | 不设则 `$DATA_DIR/backups`              |
| `RCLONE_REMOTE` | —（`backup.sh` 读） | 设了但镜像里没有 rclone，会告警跳过     |

### 模型与规划

| 变量                                                                              | 默认                                     | 说明                                         |
| --------------------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------- |
| `PROVIDER_PRIORITY`                                                               | `mock`                                   | 逗号分隔，靠前的优先；没配 key 的自动跳过    |
| `ARK_API_KEY` / `ARK_BASE_URL` / `ARK_IMAGE_MODEL`                                | — / 方舟 / `doubao-seedream-4-5-250828`  | 火山方舟                                     |
| `DASHSCOPE_API_KEY` / `DASHSCOPE_BASE_URL` / `WANX_EDIT_MODEL` / `WANX_T2I_MODEL` | — / 百炼 / `wan2.6-image` / `wan2.6-t2i` | 通义万相                                     |
| `LLM_PLAN_PROVIDER`                                                               | `mock`                                   | `mock`=规则式离线可跑；`openai`=任意兼容端点 |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`                                      | 百炼兼容端点 / — / `qwen-plus`           | `LLM_API_KEY` 同时被内容审核复用             |

> 以前这里有个 `IMAGE_FALLBACK_TO_MOCK`，定义了但从没被读，已于 09-24 删除。
> 降级只看 `PROVIDER_PRIORITY`：mock 不写进去就绝不参与，不存在"真模型失败静默变占位图"。

### 配额、成本与超时

| 变量                     | 默认     | 说明                                        |
| ------------------------ | -------- | ------------------------------------------- |
| `PER_USER_DAILY_CALLS`   | `30`     | 新用户注册时写进个人配额；管理员是它的 4 倍 |
| `DAILY_BUDGET_YUAN`      | `200`    | 全局日成本熔断                              |
| `WORKER_CONCURRENCY`     | `3`      | 同时在跑的任务数                            |
| `TASK_TIMEOUT_MS`        | `120000` | 超时会**真的取消上游请求**并退还预扣        |
| `TASK_MAX_RETRY`         | `1`      | 0-3                                         |
| `CLIENT_STEP_TIMEOUT_MS` | `60000`  | 浏览器端步骤的回执等待                      |

### 上传与图片

| 变量                  | 默认   | 说明                             |
| --------------------- | ------ | -------------------------------- |
| `MAX_UPLOAD_MB`       | `20`   | 单张                             |
| `MAX_UPLOAD_TOTAL_MB` | `60`   | 一次请求的总量（四个字段一起发） |
| `EDIT_COPY_MAX_EDGE`  | `2048` | 前端压出的编辑副本长边           |
| `THUMB_MAX_EDGE`      | `256`  | 缩略图长边                       |

### 内容安全与引导

| 变量                                     | 默认      | 说明                                                                 |
| ---------------------------------------- | --------- | -------------------------------------------------------------------- |
| `MODERATION`                             | `none`    | `qwen-vl` 才审；配了却没 `LLM_API_KEY` 会拒绝启动                    |
| `MODERATION_BLOCK_WORDS`                 | 内置 9 词 | 逗号分隔；**配了是整表替换而不是追加**                               |
| `BOOTSTRAP_ADMIN_USERNAME` / `_PASSWORD` | 空 / 空   | 空则不建管理员（那之后没人能进管理页）                               |
| `BOOTSTRAP_INVITE_CODE`                  | 空        | 逗号分隔可多个；**留空也会随机造一个并打印在启动日志**，不是"不造码" |
