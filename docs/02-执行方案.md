## 2. 各阶段任务拆解

### M0 准备（2-3 天）

**任务：**

- [ ] 注册账号并建 Key：火山方舟（Seedream）、阿里云百炼（万相 + 千问），各充 ¥50 以内；记录到密码管理器。
- [ ] 本机装 PostgreSQL 16（Docker 起）、Node 22、pnpm。
- [ ] 初始化 monorepo：
  ```
  ai-retouch/
  ├── apps/web/        # Vite + React 19 + TS
  ├── apps/server/     # Fastify + TS + Drizzle
  ├── packages/shared/ # zod schema、工具注册表（两端共享）
  ├── docker-compose.yml   # postgres + server + web(prod)
  └── .env.example
  ```
- [ ] `packages/shared` 里定义 `ToolDefinition`、`ProviderRequest`、`Capability`、SSE 事件类型 —— 这是全项目的"宪法"，两端引用同一份类型。
- [ ] Mock Provider：`submit()` 延时 2s，返回一张带参数字幕的占位图（用 sharp 现绘即可）。
- [ ] 前端骨架：路由 `/studio`（工具箱）、`/editor/:id`；SSE hook `useEventStream()`；Zustand + TanStack Query 接线。
- [ ] 服务端骨架：Fastify + drizzle migrate + pg-boss 启动 + `/api/health`。

**验收：** 打开 `/studio` 点"生成"，进度条经 `queued → running → 100%` 后显示一张 Mock 图；重启服务器后任务记录还在。

**常见坑：** pg-boss 的 schema 要和业务表分 schema 管理；Vite proxy 配好 `/api` 避免 CORS 折腾。

---

### M1 骨架打通（第 1 周）

**任务：**

- [ ] 上传链路：`POST /api/uploads`（multipart）→ sharp 生成「原图 + 编辑副本(≤2048) + 缩略图」三份，落 `/data/images/{userId}/`。
- [ ] 图片访问：`/api/images/:id` 按归属校验后流式返回（开发期直接静态目录 + 随机文件名）。
- [ ] 任务链路：`POST /api/tasks` → 配额检查 → 入队 → worker 取任务 → Provider 调用。
- [ ] **Seedream 适配器**：先用最简单的「图生图/编辑」接口跑通，注意字段差异（图片传 URL 还是 base64、尺寸枚举）全部封在适配器内。
- [ ] SSE 全链路：worker 发事件 → 进程内 EventEmitter → `GET /api/events` 按用户推送 → 前端 hook 更新任务卡片。
- [ ] 断线重连：`Last-Event-ID` 重放（内存环形缓冲 200 条/用户）+ 重连后拉进行中任务兜底。
- [ ] 登录：邀请码注册 + 密码登录 + JWT httpOnly Cookie；`/api/me` 返回配额。
- [ ] 配额扣减：任务创建时检查 `usage_daily`，成功后按 `cost_yuan` 记账；失败/审核不过不扣。

**验收：** 两个浏览器（你 + 一个测试账号）同时登录，A 发起编辑，B 的页面不会收到 A 的事件；A 断线 10 秒重连后仍能看到任务完成结果；当日第 31 次 AI 调用被拒绝并提示剩余量。

**常见坑：** SSE 默认会被某些网关缓冲 —— 记得响应头 `X-Accel-Buffering: no`；每次生成后立刻把结果写入 images 表再发事件，避免前端拿着还没落盘的文件。

### M2 工具箱（第 2 周）

**任务（按依赖顺序）：**

- [ ] 工具注册表落地：`defineTool` + 表单自动生成（从 zod schema 生成控件：图选择、滑块、文本框、尺寸选择）。
- [ ] 工具箱页面交互定型：左侧工具列表 → 中间参数表单 → 右侧结果区（单图对比 / 文生图四宫格候选）。
- [ ] P0 工具逐个接通（每个工具 = 适配器方法 + 表单 + 结果落地 + 记账）：
  - [ ] 文生图（四宫格候选，点选后成为当前图）
  - [ ] 抠图（分割 API；产出透明 PNG）
  - [ ] 换背景（抠图 + 生成：两步串成一个工具，对用户是一步）
  - [ ] 消除 / 去水印（前端框选或涂抹出 mask → inpainting）
  - [ ] 局部替换（mask + 描述词）
  - [ ] 扩图（指定比例/方向）
  - [ ] 超分（2x/4x）
  - [ ] 调色（11 参数，**纯前端实现**，实时预览，零成本零延迟）
- [ ] 内容审核接入：上传与生成结果统一过审核，拒绝路径有明确文案。
- [ ] 历史记录页：任务列表（状态筛选、重看结果、重新下载、删除）。
- [ ] 管理员页（最简）：邀请码生成、用户配额调整。

**验收：** 拿 8 张真实照片（人像/商品/老照片/带水印图/截图）各跑一遍对应工具，每张结果可下载；审核拒绝的图有提示且未扣配额；调色滑块拖动时预览 60fps 不卡。

**常见坑：** 各模型对输入尺寸/格式的处理不一致 —— 适配器统一做"入参归一化 + 必要时的本地预处理（sharp 转格式/裁边）"；mask 要给模型前先做羽化，否则接缝明显。

### M3 画布编辑器（第 3-4 周）

**第 3 周：地基**

- [ ] 文档模型：`{ w, h, layers: Layer[], sourceImageId }`；Layer 类型先做 `image / mask / text(占位)` 三种。
- [ ] Konva Stage：视口缩放（光标锚点）、空格平移、适配/1:1 快捷键。
- [ ] 图层操作：增删、显隐、排序、不透明度；缩略图列表 UI。
- [ ] 变换：Transformer（移动/缩放/旋转），栅格化时机与精度处理（松手才渲染全质量）。
- [ ] 撤销重做：文档快照栈（结构共享，容量 50），**AI 结果也进栈**。
- [ ] 文档持久化：JSONB 存 `documents`，防抖自动保存；切换文档回来不丢图层结构。
- [ ] 导出：合成可见图层 → PNG/JPEG/WebP + 尺寸倍率；大图导出走服务端 sharp（前端算力不够时）。

**第 4 周：对比与选区**

- [ ] 前后对比滑杆（拖拽 + 按住空格切换原图）。
- [ ] 选区工具：矩形 / 套索 → 生成 alpha mask 图层（可视化虚线蚂蚁线）。
- [ ] 笔刷遮罩：大小/硬度/橡皮擦，`[` `]` 调大小；涂抹结果即 mask。
- [ ] 选区直连服务端工具：选中区域 → 消除 / 局部替换（打通 M4 的前置）。
- [ ] 图层拆分（P1，提前到这里顺手做）：抠图 API → 主体层 + 背景层（背景用 inpainting 补洞）；可选 OCR 文字层。
- [ ] 性能：大图降采样编辑（编辑副本 2048），离屏缓存图层，拖动时用低精度预览。

**验收：** 连续 20 步混合操作（手动变换 + 2 次 AI 编辑）后，撤销 20 次能精确回到初始状态；拖一个 4000px 图层 60fps；刷新页面图层/选区状态完整恢复；导出的图与画布所见一致（比对像素尺寸与内容）。

**常见坑：** Konva 的 `Transformer` 与自定义视口缩放的嵌套变换要用绝对坐标换算，否则手柄漂移；撤销栈里存快照要用结构共享（immutable 更新）否则大文档内存暴涨。

### M4 Agent（第 5 周）

**任务：**

- [ ] 规划器：把工具注册表序列化为 function-calling schema；提示词版本化到 `services/agent/prompts/plan.v1.ts`；要求输出 `{ steps: [{ id, tool, params, deps, reason }] }`，步数 ≤6。
- [ ] 校验器（纯代码）：白名单 → zod 校验 → 参数钳制 → 依赖补全 → 环检测（DFS）→ 拓扑排序；失败打回重规划一次（附错误原因）。
- [ ] 执行器：前端工具走 SSE 下发指令 + 回执；服务端工具走任务队列；每步结果写 `plan_steps`。
- [ ] 计划卡片 UI：步骤列表（工具名 + 参数摘要 + reason）、确认执行、单步重试、取消、手动删步改参。
- [ ] 多轮上下文（P1）：最近 5 步操作摘要 + 文档状态摘要喂回；支持"再亮一点"这类相对指令（在本轮计划上增量重排）。
- [ ] 错误人话化：provider 错误/审核拒绝/超时，映射为可读文案 + 建议动作。

**验收（用固定测试集回归，成为项目财产）：**

- [ ] "背景换成纯白，然后把图片裁成 1:1" → 2 步计划，执行后画布正确。
- [ ] "把左边那个路人去掉"（先手动画了选区）→ 消除步骤引用现有选区成功。
- [ ] "先超分到 4x 再调成黑白" → 前端步骤与服务端步骤混排，顺序正确。
- [ ] 故意输入一个工具做不了的需求（"把这张图变成视频"）→ 明确拒绝并解释，不产生垃圾计划。
- [ ] 执行中杀掉一个 API 调用（断网/改 key 模拟）→ 单步失败，重试按钮可恢复，已完成的步骤保留。

**常见坑：** 规划模型爱"加戏"（多输出无关步骤）—— 在 schema 上限死步数与工具枚举，比在提示词里劝它有效；相对参数（"再亮一点"）要在校验器里做基准值补全。

## 3. 部署方案（国内小范围分享）

**推荐拓扑：阿里云/腾讯云轻量服务器 2C4G（~70-100 元/月）+ 香港备选**

```
            ┌── Caddy（自动 HTTPS，反代 + SSE 透传）──┐
公网 ──────▶│  web: 静态文件（Vite build 产物）       │
            │  server: Node 服务（API + worker + SSE）│
            │  postgres: 16（仅内部网络）             │
            └── /data 卷：图片 + pg_dump 备份 ────────┘
```

- **Docker Compose 三个服务**（web / server / postgres），`server` 内跑 pg-boss worker（单进程，先不拆）。
- **Caddy 关键配置**：SSE 路由 `flush_interval -1` + `X-Accel-Buffering: no`；静态资源 `Cache-Control: max-age=31536000`（带 hash 文件名）。
- **域名与备案**：国内服务器 + 域名提供 Web 服务需要 ICP 备案；图省事可先用「IP + 端口」或「香港轻量 + 域名」开局，之后再备案迁回。
- **备份**：cron 每日 `pg_dump` + 每周图片目录 rclone 到 OSS/COS，保留 14 天；备份脚本本身也要进 repo。
- **监控最简版**：`/api/health` 探活 + 每日用量/成本邮件或 TG 通知（一个 cron 脚本即可）；错误日志落文件 + `error.message` 统一格式，出错能定位到 taskId。
- **回滚**：镜像 tag 化（`retouch:20260921-1`），出事按 tag 回滚，5 分钟内完成。

**环境变量清单（`.env`）**：`DATABASE_URL`、`JWT_SECRET`、`ARK_API_KEY`（火山）、`DASHSCOPE_API_KEY`（百炼）、`PROVIDER_PRIORITY`（如 `seedream,wanx`）、`DAILY_BUDGET_YUAN`、`PER_USER_DAILY_CALLS`、`MODERATION_ENABLED`、`DATA_DIR`。
